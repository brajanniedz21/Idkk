# Agent 2.2 — Long-Form Image Sourcer

## Role
Generate an original background image matching the aesthetic described in Agent 1.2's brief. This agent replaces the originally-proposed Pinterest-scraping approach, which was rejected for ToS/copyright reasons — every image here is newly generated, never scraped or copied. This is the one long-form stage with a hard environmental dependency that can fail for reasons entirely outside the agent's control — read the troubleshooting note below before assuming a failure is something you did wrong.

## Inputs
- Candidate brief from `state/long_form_queue.json` (`visual_theme`, `mood`) with status `scouted`
- The `banana` skill (Nano Banana / Gemini image generation) — requires a configured Google AI/Gemini API key with actual usable quota; see the troubleshooting section below
- As of 2026-07-27, an alternate path B: owner-supplied images (see "Path B" section below) — use only when the owner has explicitly handed over a source folder/file for a candidate, never as a default substitute for generation.
- **PRIMARY as of 2026-07-29: Path C, `state/animated_clip_pool.json`** — the owner now supplies short pre-animated clips (not static images) for this stage to pull from directly. Check this pool first; only fall back to Path A (banana generation) or Path B (legacy static images) if it's exhausted, and flag to the owner rather than falling back to a legacy folder (see that file's `_comment` and `agents/0_orchestrator.md`'s Never-do list — the "never fall back to an old source" rule applies here too). When sourcing from Path C, record `source: "owner_ai_generated_clip"` and set the candidate's status to `image_sourced` same as the other paths (Agent 3.2 reads whichever path was used the same way) — Agent 3.2 no longer adds motion itself, it builds a ping-pong loop from the clip you hand it, so don't also try to keep the clip static.

## Method
1. Invoke the `banana` skill to generate a high-resolution (at least 1920x1080, ideally 4K if the model supports it without excessive cost) still image matching `visual_theme`: composition, color grade, and mood should echo the reference long-form examples in `config/channel.json` without copying any specific real photo.
2. Generate 2-3 variations if the first pass doesn't clearly match the brief; pick the best.
3. Save to `assets/long-form/images/<candidate_id>.png` (or the highest-quality format the tool returns).
4. Confirm the `long_form_gates.image_copyright_gate` check trivially: the image must be a `banana`-generated output, not a downloaded/fetched photo from any external source. If for any reason a real photo was fetched (e.g. as a style reference passed into the generation), the *output* must still be a generated image, not the reference itself re-saved.

## If the `banana` skill fails — a real, already-encountered failure mode
This has genuinely happened once already (`lf_001`) and is worth diagnosing carefully rather than assuming it's a transient error:
1. Run `python3 /root/.claude/skills/banana/scripts/validate_setup.py` — this checks whether an API key is configured at all (env var, MCP server registration, `~/.banana` config). If it reports failures, no key is present — this is a one-time setup gap, not something fixable by retrying the generation.
2. If a key **is** configured but generation still fails with a `429`/`RESOURCE_EXHAUSTED` error, check the exact error message. A message citing `generate_content_free_tier_requests, limit: 0` (a hard **zero**, not "exceeded for today") means the underlying Google Cloud project has no usable quota at all — this is not a rate limit you can wait out. Confirm this isn't image-specific by also testing a plain text `generateContent` call against the same key directly via `curl` to `generativelanguage.googleapis.com` — if that *also* returns `limit: 0`, the problem is the project's billing/quota setup, not anything about the image request itself, and no amount of retrying, prompt-adjusting, or model-switching will fix it.
3. **Do not substitute a non-generated image as a workaround** if generation is blocked — this would violate the `image_copyright_gate` outright (scraped/placeholder images are never permitted, no exceptions). Instead, quarantine the candidate with a specific, technical explanation (not "generation failed," but "the configured Gemini API key returns limit:0 across both text and image models, indicating a project-level quota/billing issue, not a code or prompt problem") and preserve the brief (and any audio already sourced for it) for reuse once a working key is available. This is a one-time setup gap for the channel owner to resolve (a free-tier Google AI Studio key at https://aistudio.google.com/apikey, or enabling billing if free tier isn't available in that account's region) — not something Agent 2.2 can fix from inside a cycle.

## Output
Append `{image_path, generated_at, prompt_used}` to `state/image_pool.json`, update the candidate's entry in `state/long_form_queue.json` with `image_path`, set status to `image_sourced`.

## Never do
- Never fetch, download, or reuse a real photo (Pinterest, Google Images, stock sites requiring attribution/license you haven't verified) as the final background. Generation only.
- Never skip straight to Agent 3.2 without confirming the image actually matches the brief's mood — a mismatched image undermines the whole video's aesthetic consistency.
- Never treat a quota/billing failure as a content or prompt problem — diagnose which it actually is before spending effort retrying the wrong fix.
- **Never crop down a Path B owner-supplied source image, including when reusing one across two candidates (owner direction, 2026-07-28).** These stills are already small (roughly 700-750px wide) before being upscaled to fill a 1920x1080 frame; cropping tighter only throws away resolution and makes the output blurrier. If a source image must be reused for a second candidate, keep it at full resolution and differentiate the two videos via Agent 3.2's pan/zoom treatment and a distinct color grade/mood/audio track instead — see `agents/long_form/3.2_animator.md`'s "Never do" section.
- **Never pull an image from the legacy Drive folder (`1eDQ9-NyZ1ko8WTmaNSDtrNwQUFuQI24g`) for a new candidate, for any reason, including the active pool running low (owner direction, 2026-07-28, absolute).** Flag it to the owner and wait instead.
