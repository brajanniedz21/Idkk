# Agent 3.2 — Animator

## Role
Take Agent 2.2's sourced short animated clip and turn it into a seamlessly-loopable segment so the long-form video isn't a dead static frame or an obviously-repeating clip for hours. As of 2026-07-29 (owner direction), the source is already a short *animated* AI-generated clip (not a static image) — this stage's job is exclusively to build the ping-pong loop below, not to invent motion treatments. The rain-overlay approach used briefly on 2026-07-28 is scrapped; don't resurrect it.

## Inputs
- Clip path from `state/long_form_queue.json` (status `image_sourced` — field name kept for continuity, it now holds the sourced *clip* path)
- `state/animated_clip_pool.json` — the active clip pool/folder

## Method — ping-pong loop with a speed ramp at the cut (owner-approved, finalized 2026-07-29)
1. Take the sourced clip (typically ~5-6s) and apply a **deceleration ramp to its last ~1.5s**: split that tail into several short chunks (5 chunks of ~0.3s worked well) with progressively slower `setpts` multipliers (e.g. 1.0, 1.2, 1.45, 1.75, 2.2), concatenated back onto the untouched head. This makes the clip ease into a near-stop right at its end instead of cutting at full speed.
2. Build the reversed half **from that same ramped clip**, not the original — `reverse` a clip whose tail is already slowed automatically gives a reversed clip whose *start* is slow too, so the deceleration/acceleration is symmetric around the cut with no extra work.
3. Concatenate ramped-forward + reversed-ramped to get one ping-pong unit. Because the forward clip's last frame is identical to the reversed clip's first frame, and the reversed clip's last frame is identical to the forward clip's first frame, **both loop points are exact — no crossfade needed.**
4. Scale to 1920x1080 with `flags=lanczos` and **no crop** (see "Never do" below).
5. Export the ping-pong unit as the loop segment (e.g. `assets/long-form/output/<candidate_id>_loop_segment.mp4`), silent — Agent 5 repeats this via `-stream_loop` to fill the target runtime, same as before.

Reference recipe (generate the ramp segments programmatically — this was built as a small Python loop emitting the `trim`/`setpts` filter lines, not typed by hand):

```
[0:v]trim=0:<ramp_start>,setpts=PTS-STARTPTS[main];
[0:v]trim=<a0>:<b0>,setpts=(PTS-STARTPTS)*1.0[r0];
[0:v]trim=<a1>:<b1>,setpts=(PTS-STARTPTS)*1.2[r1];
[0:v]trim=<a2>:<b2>,setpts=(PTS-STARTPTS)*1.45[r2];
[0:v]trim=<a3>:<b3>,setpts=(PTS-STARTPTS)*1.75[r3];
[0:v]trim=<a4>:<b4>,setpts=(PTS-STARTPTS)*2.2[r4];
[main][r0][r1][r2][r3][r4]concat=n=6:v=1:a=0[ramped];
[ramped]scale=1920:1080:flags=lanczos,format=yuv420p,split[fwd][rev0];
[rev0]reverse[rev];
[fwd][rev]concat=n=2:v=1:a=0[v]
```
`ramp_start` = clip duration minus 1.5s; the 5 `[aN]:[bN]` windows are that last 1.5s split into equal steps. Encode with `-c:v libx264 -preset medium -crf 16-18 -pix_fmt yuv420p`.

## Output
Update candidate entry in `state/long_form_queue.json` with `animated_loop_path`, set status to `animated`.

## Never do
- Never ship a loop segment with a visible seam/jump at either loop point (the ping-pong cut, or the wrap from Agent 5's repeat) — verify by frame-sampling before calling this done.
- Never re-add the rain overlay treatment — scrapped by the owner 2026-07-29. If a future owner request revives it, treat it as a new request, not a resurrection of the old recipe.
- **Never crop a long-form source asset down to make a reused one "feel distinct" (owner direction, 2026-07-28).** These clips/stills are relatively low-resolution before upscaling to 1920x1080 — cropping further throws away resolution and makes the output blurrier, not more distinct. This is the opposite of short-form, where cropping to vertical is a *required* copyright-mitigation step (see `agents/short_form/3.1_producer.md`) — that rule does not apply here. If an asset must be reused across two candidates, differentiate via ramp timing/amplitude and color grade/mood instead, at full original resolution.
- Never apply a color-correction pass unless the clip actually went through some other filter first — this stage's ping-pong recipe doesn't need one (no blend mode involved), so don't add one by default.
