# Agent 3.2 — Animator

## Role
Take Agent 2.2's sourced short animated clip and turn it into a seamlessly-loopable segment so the long-form video isn't a dead static frame or an obviously-repeating clip for hours. As of 2026-07-29 (owner direction), the source is already a short *animated* AI-generated clip (not a static image). As of 2026-08-01 (owner direction), this stage's job has two parts: first **decide** which loop-construction method actually fits the clip's visible motion, then **build** the loop with that method. The rain-overlay approach used briefly on 2026-07-28 is scrapped; don't resurrect it.

## Inputs
- Clip path from `state/long_form_queue.json` (status `image_sourced` — field name kept for continuity, it now holds the sourced *clip* path)
- `state/animated_clip_pool.json` — the active clip pool/folder
- The clip's source-generation prompt or scene metadata, if available (supporting evidence for the motion decision below — never the sole basis for it)

## Step 1 — Intelligent loop-method selection (owner direction, 2026-08-01)

Before building anything, decide **reverse** (the existing ping-pong method, below) or **crossfade** (new, below) based on the clip's *actual visible motion* — never on the objects present, the filename, or the source prompt alone (those are supporting evidence at most).

1. Run `python3 scripts/loop_contact_sheet.py --input <clip> --output <candidate_id>_contact_sheet.png --frames 10` (8-12 is the valid range) — this is purely mechanical frame extraction/tiling, it makes no decision itself.
2. **Actually look at the contact sheet** (via the Read tool — same discipline as the thumbnail billboard-preview check in `agents/long_form/6_publisher.md`). Determine:
   - Does the camera move (pan/zoom/tilt/dolly/parallax)?
   - Does a recognizable subject (person, animal, vehicle, door, any foreground object) change position or pose?
   - Is any movement localized/coherent (an animal, a vehicle) as opposed to diffuse/non-coherent ambient particles (snow, rain, fog, mist, dust, ripples, light flicker)?
   - **Major-subject or camera movement always takes priority over ambient movement** — a clip with both falling snow *and* a visibly moving person/animal/vehicle/object/camera is `reverse` (the mixed-scene rule).
   - **If genuinely uncertain, default to `reverse`** — a slight reverse is safer than visible crossfade ghosting. Don't force a `crossfade` call past reasonable doubt just because the scene looks static at a glance: a clip that reads as "static" across 10 sampled frames can still have real motion (baked-in camera drift, an evolving atmospheric effect like mist that thickens over the clip's duration) that only shows up as a double-exposure once you actually build and inspect the crossfade blend region — see the verification step below, which exists specifically to catch this.
3. Record the decision as structured JSON (validate with `scripts/motion_decision.py`'s `validate_decision()`):
   ```json
   {
     "loop_method": "reverse" | "crossfade",
     "confidence": 0.0,
     "significant_subject_motion": true | false,
     "camera_motion": true | false,
     "motion_summary": "Short description of what moves",
     "reason": "Why this method was selected"
   }
   ```
4. Log it via `scripts/motion_decision.py`'s `format_log_line()` (or let `scripts/loop_builder.py --decision <file>` print it for you, below) — every candidate's log must show something like:
   ```
   Loop method: crossfade
   Confidence: 0.94
   Motion: Falling snow and faint drifting fog; camera and main scene are static
   Reason: Only continuous ambient motion is present, so reversing would make the snow rise unnaturally
   ```

## Step 2 — Build the loop with `scripts/loop_builder.py`

```
python3 scripts/loop_builder.py --input <clip> --output <candidate_id>_loop_segment.mp4 \
  --method <reverse|crossfade> --decision <candidate_id>_motion_decision.json
```

Both methods output a silent, 1920x1080 loop segment — Agent 5 repeats whichever one via `-stream_loop` to fill the target runtime, same as before; it doesn't need to know or care which method built the file.

### `reverse` — ping-pong loop with a speed ramp at the cut (owner-approved, finalized 2026-07-29; **unchanged**, now lifted into `scripts/loop_builder.py`'s `build_reverse_loop()` instead of being hand-built each time)
Use when a distinct subject or the camera moves enough that a crossfade would ghost: a person/animal/vehicle changing position or pose, a door opening, any foreground object changing position, camera pans/zooms/tilts/dollies/parallax, or a scene mixing ambient particles with real subject motion.

1. Apply a **deceleration ramp to the clip's last ~1.5s**: split that tail into 5 chunks of ~0.3s with progressively slower `setpts` multipliers (1.0, 1.2, 1.45, 1.75, 2.2), concatenated back onto the untouched head. This eases the clip into a near-stop right at its end instead of cutting at full speed.
2. Build the reversed half **from that same ramped clip**, not the original — reversing a clip whose tail is already slowed automatically gives a reversed clip whose *start* is slow too, so the deceleration/acceleration is symmetric around the cut with no extra work.
3. Concatenate ramped-forward + reversed-ramped. Because the forward clip's last frame is identical to the reversed clip's first frame (and vice versa), **both loop points are exact — no crossfade needed.**
4. Scale to 1920x1080 with `flags=lanczos` and **no crop** (see "Never do").
5. Never reverse the separate ambient audio track — this method (and `scripts/loop_builder.py` generally) only ever touches the video stream; Agent 5 sources/loops audio completely independently.

### `crossfade` — direct video dissolve loop (new, 2026-08-01)
Use when the camera and major subjects are stationary and the only movement is continuous, *symmetric* ambience: falling snow/rain, drifting fog/mist/smoke/clouds, floating dust, subtle light flicker/glow, gentle water ripples, small leaf/grass movement, or a stationary car/scene with only rain/mist/lighting movement.

1. Crossfade duration: `min(2.0, max(0.6, source_duration * 0.12))`, shrunk further if needed so a clean middle section always remains (see `build_crossfade_loop()`'s `min_clean_middle` guard — never let the crossfade eat the whole clip).
2. Construct a genuinely repeatable loop unit, not a dissolve stitched onto two copies with a hard cut elsewhere: begin the loop after the portion used as the incoming side of the blend, play the central section normally, then at the end blend the final frames into the opening frames (`xfade` with `transition=fade` — a direct dissolve, never through black) so the loop finishes on the exact point where the next repetition begins.
3. Repeat this completed loop unit (Agent 5's job, via `-stream_loop`) — never place a single dissolve between two copies while leaving a hard cut elsewhere in the sequence.
4. No black frames, brightness flashes, frozen frames, or duplicated audio (this method touches video only, same as reverse).

### Verification (required for every candidate, not optional)
Frame-sample the built loop segment before marking the candidate `animated`:
- Extract frames near the very start, and near/just-past the loop point (e.g. `ffmpeg -ss <t> -i <loop_segment> -vframes 1 <frame>.png`), and actually look at them.
- **For `crossfade` specifically: extract and look at a frame from the *middle* of the blend region** (not just its start/end) — this is what catches an asymmetric ambient effect (e.g. mist/haze that's genuinely uniform-looking across 10 sparse contact-sheet samples but turns out to thicken unevenly across the clip) producing a visible double-exposure ghost that a coarse contact-sheet inspection can miss entirely. If the mid-blend frame shows any ghosting/doubling, that's a real defect, not a false alarm — redo the decision as `reverse` instead of shipping it, and note in the decision log that the switch was made after an empirical crossfade check failed, not from the original contact-sheet read.
- Confirm no visible seam/jump at either loop point (the construction method's own internal loop point, or the wrap from Agent 5's `-stream_loop` repeat).
- Confirm the loop plays back at the resolution/frame rate/duration expected — neither method should ever produce a shorter or longer segment than its own internal math implies.

## Output
Update candidate entry in `state/long_form_queue.json` with `animated_loop_path`, the `motion_decision` object from Step 1, and set status to `animated`.

## Never do
- Never pick a loop method from the objects present or the filename/prompt alone — the decision must be based on actually looking at the contact sheet frames (and, for crossfade, the built blend region).
- Never ship a loop segment with a visible seam/jump at either loop point (the construction method's own cut, or the wrap from Agent 5's repeat) — verify by frame-sampling before calling this done.
- Never ship a `crossfade` candidate without actually inspecting a frame from the *middle* of its blend region — a clean-looking contact sheet is not proof the blend itself is clean (see the mist/haze failure mode documented in the Verification section above; it's a real failure mode this pipeline has hit, not a hypothetical).
- Never re-add the rain overlay treatment — scrapped by the owner 2026-07-29. If a future owner request revives it, treat it as a new request, not a resurrection of the old recipe.
- **Never crop a long-form source asset down to make a reused one "feel distinct" (owner direction, 2026-07-28).** These clips/stills are relatively low-resolution before upscaling to 1920x1080 — cropping further throws away resolution and makes the output blurrier, not more distinct. This is the opposite of short-form, where cropping to vertical is a *required* copyright-mitigation step (see `agents/short_form/3.1_producer.md`) — that rule does not apply here. If an asset must be reused across two candidates, differentiate via ramp timing/amplitude and color grade/mood instead, at full original resolution.
- Never apply a color-correction pass unless the clip actually went through some other filter first — neither loop method needs one (no blend mode affecting color), so don't add one by default.
- Never reverse the separate ambient audio track under either method — audio is sourced/looped entirely by Agent 4.2/Agent 5, independently of whichever video loop method this stage picks.
