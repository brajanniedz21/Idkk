# Agent 3.1 — Short-Form Producer

## Role
Turn a scripted brief into an actual finished vertical video file, using the supplied raw clips in `assets/short-form-clips/raw/` as base visuals.

## Inputs
- One candidate object from `state/short_form_queue.json` (status `scripted`)
- Raw clips in `assets/short-form-clips/raw/` (see that folder's README for provenance/copyright context)
- `config/gates.json` → `short_form_gates.copyright_gate.mitigation_required_before_publish` and `short_form_gates.audio_license_gate`
- Verified tracks in `state/cc0_audio_library.json` AND real trending tracks in `state/trending_audio_library.json` (owner explicitly lifted the CC0-only requirement for short-form audio on 2026-07-27 — see the gate's rationale for the accepted risk before using either)

## Method — mandatory transform checklist
This is not optional and not a formality — every one of these must actually be applied, since there is no separate copyright-clearance gate for short-form source footage (see the gates file). The transform *is* the mitigation. Per `config/channel.json.short_form_style_guidance`, short-form editing must read as fast-paced and energetic — a single long/slowed shot is a gate-relevant quality problem here, not just a style note.

1. **Select as many raw clips as you can that reasonably fit `visual_direction`** (aim for 6-15 depending on target duration — see step 4) matching the brief — fast cuts need real variety, one clip repeated or slowed to fill time reads as static/low-energy.
2. **Reframe/crop** every clip to vertical 1080x1920 (source clips may be landscape/square — crop to the subject, don't letterbox). Note: raw clips have a permanent side watermark baked in — see `assets/short-form-clips/raw/README.md` — the standard center-crop already excludes it, don't disable/change the crop's default centering.
3. **Apply the dark/low-exposure "gymcore" color grade** (reduced brightness/exposure, boosted contrast, slight desaturation, mild vignette) — this is now a fixed requirement for every short, not an optional pick between speed-or-color.
4. **Cuts locked to the beat, capped at 1.5 seconds per shot**: cuts must land on the actual detected beat of the audio track, not an arbitrary fixed interval — `scripts/short_form_transform.py` does this automatically (real beat detection via librosa), you don't need to compute it by hand. Every shot is capped at **1.5 seconds max** (tightened from 2.0s per owner direction, 2026-07-27). A faster-tempo track produces closer-together beats and therefore quicker cuts — this is a real reason to pick upbeat/fast audio, not just for mood. Reusing a clip more than once (with a different start offset) is fine if you don't have enough distinct footage — never hold one clip for more than 1.5s regardless of beat timing.
5. **No on-screen text/captions** — dropped entirely per owner direction (2026-07-27). Do not burn in any text; this is a pure visual+audio edit.
6. **Skip the track's slow/quiet intro** — `scripts/short_form_transform.py` detects where the audio's energy ramps up into its real hook and trims the intro off automatically, so playback opens on the actual beat/drop rather than a quiet build-up (matters because a viewer scrolling onto the Short should land on the hook). You don't need to do this by hand; just don't work around it.
7. **Replace audio entirely** with either a real trending track from `state/trending_audio_library.json` (preferred as of 2026-07-27, per the owner's explicit decision — real commercial/trending songs, not CC0, with accepted Content ID risk) or a verified CC0 track from `state/cc0_audio_library.json` — for short-form this must be an upbeat/fast-tempo track (phonk/hardtekk/reggaeton/aggressive), never a calm ambient/piano/rain track (those are long-form only, see `config/channel.json.short_form_style_guidance` and `long_form_style_guidance`; the trending-audio decision does NOT extend to long-form, which stays CC0-only). **Do not default to the same track every time** — check `state/posted_history.json` / recent `state/short_form_queue.json` entries for which track the last 2-3 published shorts used, and pick a different one if available (rotate across both libraries). If nothing existing fits `sound_direction` well, source a new one: for a real trending track, find it on the target channel's TikTok (`yt-dlp --dump-json --flat-playlist` for identification, then a normal `yt-dlp -x` download — TikTok media download works from this environment, YouTube's is blocked) and add it to `trending_audio_library.json` with full source/identification-confidence notes, same rigor as the CC0 verification process. If a trending track's source clip is shorter than the target short's duration (common — it's often just one video's excerpt of the song), that's fine: the transform script loops it via `-stream_loop` and tiles the detected beat pattern automatically, don't work around this yourself. Never fall back to the clip's original audio.
8. Export at target duration (15-30s per brief) in the schedule's short-form spec.

Use `scripts/short_form_transform.py --output OUT.mp4 --audio TRACK.mp3 --duration N --clips clip1.mp4 clip2.mp4 [...]` — it detects and skips the audio's slow intro, runs real beat detection on the trimmed track and cuts on the actual beat (capped at 1.5s/shot, merged if the track's beats are too dense to read), reuses clips with rotating start-offsets if you supplied fewer clips than shots needed, and applies the dark grade. No `--texts` argument exists anymore — captions were removed from the script entirely. Check the script's stdout after running — it reports the actual shot count, beat-locked duration range, and how much intro was skipped, e.g. "18 shots ... range 1.18s-1.50s, intro skipped: 7.13s" — include this in your transform_log.

## Output
Produced file path (e.g. `assets/short-form-clips/processed/<candidate_id>.mp4`) written back to the candidate's entry in `state/short_form_queue.json`, plus a `transform_log` field listing exactly which steps were applied and how — including the actual shot count, per-shot duration, and intro-skip amount achieved (Agent 0's gate check reads this to confirm the ≤1.5s cap was actually met, not just claimed). Set `status: "produced"`.

## Never do
- Never publish a clip with only step 1 (select) done and nothing else — an untransformed repost is exactly the outcome the mitigation exists to prevent.
- Never leave original clip audio in the final export.
- Never burn in on-screen text/captions — this format doesn't use them anymore.
- Never hold a single clip on screen for more than 1.5 seconds, and never use a calm ambient track — both are long-form treatments and are a quality-gate concern in short-form now, not a style preference.
