Agent 0 — Orchestrator

Agent 0 is the only agent a scheduled routine talks to directly. It never produces content itself — it reads state, decides what needs to happen this cycle, delegates each stage to the right sub-agent (via the `Agent` tool, one sub-agent per pipeline stage), enforces gates, and logs everything. It is the sole owner of `state/*.json` writes at the top level (sub-agents return results to Agent 0, which persists them — though in practice, sub-agents are often given direct Read/Edit/Write access to the state files themselves and asked to update their own candidate's entry; Agent 0's real job either way is to *verify* those writes are correct and complete before moving on, not to blindly trust a sub-agent's self-report). Think of Agent 0 as the show-runner: it doesn't write the script, shoot the footage, or pick the music — it decides what needs doing, hands each job to the right specialist, checks the work when it comes back, and is the one who has to explain to the channel owner why something did or didn't get published.

Short-form · 31 total, 16 published, 3 quarantined
1.1
Trend Scout
Find what's currently working in the "motivational luxury" Shorts/TikTok niche and produce a ranked, concrete opportunity — not just a topic, but a specific angle with a real sound-energy direction, title, and visual approach already attached, grounded in genuinely observed data rather than assumption.
2.1
Scriptwriter
Turn one scouted opportunity from Agent 1.1 into a complete, ready-to-produce brief: title, SEO metadata, and sound/visual direction — everything Agent 3.1 (Producer) and Agent 4.1 (Publisher) need, so neither has to make creative decisions of their own. Despite the name "Scriptwriter," this stage no longer writes an on-screen or spoken script at all — see below.
3.1
Producer
Turn a scripted brief into an actual finished vertical video file, using the supplied raw clips in `assets/short-form-clips/raw/` as base visuals and a track from one of the two audio libraries. This is the stage where the pipeline's real technical substance lives — everything else is planning, this is where a file actually gets rendered.
Gates
Every candidate must pass the shared and format-specific gates in config/gates.json before it can move to ready_to_publish — factual/controversy screen, platform policy check, basic QA, copyright mitigation, and audio license check. A failing candidate is quarantined with a logged reason and the next candidate is scouted instead; gates are never lowered to hit the publishing schedule.
4.1
Publisher
Publish a gate-passed short to YouTube via the YouTube Data API v3, using metadata from Agent 2.1's brief, and record the result. This is a mechanical, deterministic stage — by the time this agent runs, Agent 0 has already gate-checked the video and made the creative/quality call to publish. Agent 4.1's job is to execute the upload correctly and record what actually happened, not to second-guess the decision to publish.
Long-form · 8 total, 2 published, 1 quarantined
1.2
Format Scout
Study what's currently working for other channels in the motivational-luxury long-form ambient-video niche (aesthetic, sound vibe, title/SEO patterns) and produce a concrete brief for the rest of the long-form pipeline. Long-form here means a multi-hour ambient background video — a still, generated scene with subtle motion, looped audio, and a long runtime (60-600 minutes) — a completely different format from the fast-cut short-form pipeline, and the two should never be confused: nothing about short-form's beat-locked cuts, 1.5s cap, or dropped captions applies here. Long-form is deliberately slow, calm, and static by design.
2.2
Image Sourcer
Generate an original background image matching the aesthetic described in Agent 1.2's brief. This agent replaces the originally-proposed Pinterest-scraping approach, which was rejected for ToS/copyright reasons — every image here is newly generated, never scraped or copied. This is the one long-form stage with a hard environmental dependency that can fail for reasons entirely outside the agent's control — read the troubleshooting note below before assuming a failure is something you did wrong.
3.2
Animator
Take Agent 2.2's static generated image and add subtle ambient motion so the long-form video isn't a dead static frame for hours — light rain drift, slow zoom/parallax, flickering light, drifting clouds, etc., matched to the image's theme. This is a mood-preservation stage, not a creative-license one: the goal is "not static," not "an interesting animation in its own right."
4.2
Sound Sourcer
Select a genuinely copyright-free (CC0 / no-attribution-required) ambient track matching the mood of the reference examples, for the long-form video. "Copyright free" must be a checkable, sourced fact — never just a prompt instruction taken on faith. **Unlike short-form, long-form audio has no exception to this rule** — the owner's 2026-07-27 decision to permit real trending/commercial songs applies to short-form only (see `config/gates.json` → `short_form_gates.audio_license_gate`); a multi-hour loop of a ~15-20s commercial-song excerpt would both sound absurd on repeat and carry meaningfully higher legal exposure than a single short's use, so long-form stays CC0-only, no exceptions.
5
Assembler / Looper
Combine the animated visual loop (Agent 3.2) and the verified audio track (Agent 4.2) into the final long-form video, looped to the target runtime (60-600 minutes). This is the stage where a mistake is most expensive to redo — a multi-hour render/encode is not something to casually re-run for a small fix, so get the parameters right before starting.
6
Publisher
Publish a gate-passed long-form video to YouTube via the YouTube Data API v3, using metadata from Agent 1.2's brief, and record the result. Mirrors Agent 4.1's role for the short-form pipeline, with one significant practical difference: these files are large (a multi-hour video, potentially several GB), so the upload itself takes real time and needs to be handled as a resumable operation, not a fire-and-forget request.
